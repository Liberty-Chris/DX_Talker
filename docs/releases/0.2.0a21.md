DX Talker 0.2.0a21 improves audio resilience during desktop idle transitions.

Modern desktop playback now requests host selected buffers with high latency instead of a fixed 1024 frame callback size. Isolated output underruns can continue the current spot or local preview without disabling output. Repeated underruns, other audio faults, device loss, cancellation and deadlines still stop output. Identification underruns stop RF so an interrupted ID is not accepted as complete. There is no automatic RF restart, endpoint change or replay of a failed spot.

On Windows, Audio / PTT includes optional Keep awake choices: Off, Computer and Computer and display. Off is the default. Requests apply only while local listening, RF or a preview is active and are released on stop or output worker exit. Native Windows requests do not change Num Lock, send keystrokes, disable configured screensavers or alter lock settings. Explicit user sleep is respected.

Diagnostics add fixed audio status flags, underrun counts, host API category, selected stream latency and callback timing gaps. Windows also records sampled screensaver state changes, keep awake requests and observation gaps. No audio samples, device names, input activity or credentials are recorded. Brief screensavers between samples can be missed; a gap alone does not prove system sleep.

The repair targets the reported a15 screensaver incident whose exported report captured an audio stream fault during a spot. Automated tests use synthetic audio callbacks and simulated idle transitions; the reporting Windows 10 computer still needs a screensaver and display sleep retest. XP retains its WinMM audio adapter and gains the same optional native Windows power control. Ubuntu receives the modern callback improvements. Android listening behavior is unchanged.
