# Profile transfer and curated directories

DX Talker transfer version 2 is a UTF-8 JSON object with schema `dxtalker-transfer`, version 2, profiles and filters. Updated apps also accept version 1. Profile entries contain name and connection only. Connection contains source_type, host, port, login, feed_url and poll_seconds. Filters may contain min_khz, max_khz, max_age_seconds, repeat_seconds, spacing_seconds, frequency_unit, filter_bands, filter_modes and filter_activities. The three selection fields are comma separated validated choices; empty means all. Version 2 requires desktop/Android 0.2.0a11 or later. Older apps reject the expanded document instead of silently dropping filters. Canonical frequency filters remain in kHz.

Desktop QR selection starts with the entire saved collection selected. Keep all profiles or select a subset, then choose Generate QR codes. File exports contain all saved profiles. Both include the current filter settings. No stored password, bearer token, protected blob, radio configuration or logging path is included. Query strings in feed URLs are rejected for transfer because they may contain credentials. Enter any private URL parameters separately on the destination. Login callsigns, hostnames and filter preferences are intentionally visible to anyone who can read the QR or file; only share it with the intended operator/device.

QR text uses `DXT1:` followed by unpadded URL-safe base64 of zlib-compressed JSON. QR input is limited to 1800 bytes; decoded JSON is limited to 64 KiB and must finish without trailing compressed data. When one code cannot fit, the desktop presents numbered QR pages with Previous and Next. Every page uses `DXT2:<sha256>:<page>:<total>:<data>`, where the digest covers the complete compressed document and data is an unpadded URL-safe base64 chunk of up to 1024 bytes. There are at most 66 pages and at most 66560 compressed bytes; decoded JSON retains the 64 KiB bound. Android accepts pages in any order, ignores identical duplicate scans and rejects mixed collections or conflicting pages. No partial profile writes occur. The complete stream must match its checksum before decompression and schema validation. This checksum detects corruption, not sender authenticity. Readers validate the complete document before any writes. Unknown keys, credential fields, unsupported versions and invalid connection/filter values are rejected.

In Android, open Clusters and choose Scan desktop QR collection or Import profile file. Update Android to 0.2.0a9 or later for collection pages. Scan next continues the collection with a page count. Continue later preserves scans across activity recreation; Reset QR collection abandons the collected pages. Review the entire collection’s profile names and destinations and confirm Import. Existing profiles are kept; duplicate names get an import suffix. Imported credentials are blank. Import does not start a connection or select a destination automatically. Imported filters are used on the next listener start. Use this cluster switches an active listener to the selected connection and clears old results. Saving a profile does not select or connect it. A camera is optional because file import is also available.

The curated directory format uses schema `dxtalker-directory`, version 1 and an entries array. Each entry contains a stable id, name, connection, status (`active` or `retired`), checked (review date as text) and description. The repository's initial entries array is empty while Dad prepares the list. Do not invent active feeds or infer reachability from an old review date. Cluster directory lets the operator load a newer directory file and add an active connection with one click. Already saved connections are not duplicated. Retired entries cannot be added. Existing operator profiles are never removed automatically; Delete profile remains an explicit confirmed action.
