# Profile transfer and curated directories

DX Talker listening transfer version 4 is a UTF-8 JSON object with schema `dxtalker-transfer`, version 4 and a `filters` object. It contains active listening settings and `listening_presets`, a serialized JSON object of named filter snapshots. It has no `profiles` field. Frequencies remain in kHz. The reader rejects unsupported fields and validates each preset as well as the active filters.

Desktop Filters → Send to phone exports version 4 as QR or a file. Source → Export profiles retains the legacy file format. The reader accepts versions 1 through 3 with `profiles` and `filters`. Legacy profile entries contain a name and connection fields for source type, host, port, login, feed URL and polling interval. Passwords and tokens stay local. Legacy export rejects feed URLs with query strings.

QR text uses `DXT1:` followed by unpadded URL-safe base64 of zlib-compressed JSON. QR input is limited to 1800 bytes; decoded JSON is limited to 64 KiB and must finish without trailing compressed data. When one code cannot fit, the desktop presents numbered QR pages with Previous and Next. Every page uses `DXT2:<sha256>:<page>:<total>:<data>`, where the digest covers the complete compressed document and data is an unpadded URL-safe base64 chunk of up to 1024 bytes. There are at most 66 pages and at most 66560 compressed bytes; decoded JSON retains the 64 KiB bound. Android accepts pages in any order, ignores identical duplicate scans and rejects mixed collections or conflicting pages. No partial profile writes occur. The complete stream must match its checksum before decompression and schema validation. This checksum detects corruption, not sender authenticity. Readers validate the complete document before any writes. Unknown keys, credential fields, unsupported versions and invalid connection/filter values are rejected.

In Android, open Filters and choose Scan listening QR or Import listening file. Review the settings and confirm the import. Active filters take effect on the current listener. Existing presets are preserved and conflicting names with different values receive an import suffix. The combined presets must fit the existing size and count limits. Cluster connections remain local to the device. Older cluster profile files remain available through Clusters → Import profile file.

The curated directory format uses schema `dxtalker-directory`, version 1 and an entries array. Each entry contains a stable id, name, connection, status (`active` or `retired`), checked (review date as text) and description. The bundled directory contains the reviewed recommendations. Android preloads active entries when its saved cluster list does not yet exist. Do not invent active feeds or infer reachability from an old review date. Cluster directory lets the operator load a newer directory file and add an active connection with one click. Already saved connections are not duplicated. Retired entries cannot be added. Existing operator profiles are never removed automatically; Delete profile remains an explicit confirmed action.
